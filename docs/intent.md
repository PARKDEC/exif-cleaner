# Exif Cleaner — 구현 기준

2026-11-23 대화 기준. 사용자가 구조 검토 후 실제 구현을 요청했다.

## 목적

본인이 생성한 이미지를 공유하기 전에, NAI Inspect 등에서 이미지에 저장된 생성 프롬프트를 읽어 재사용하는 경로를 줄인다. 처음 의도 문서의 EXIF 제거만으로는 이 목적을 충족하지 못하므로, 일반 생성 메타데이터와 알려진 stealth PNGinfo 형식까지 처리한다.


## 사용 흐름과 제약

- 개인용 Windows 앱을 더블클릭하여 창을 연다.
- 파일·폴더 추가 버튼 또는 탐색기에서 창의 드롭 구역으로 입력한다. 여러 파일·폴더를 함께 추가할 수 있다.
- 개별 파일을 넣으면 그 파일만, 폴더를 넣으면 바로 안의 PNG·JPG 파일만 처리한다. `.jpeg`는 JPG와 동일한 형식으로 취급한다.
- 파일·폴더마다 작업을 등록하고 한 번에 하나씩 등록 순서대로 처리한다. 이미 처리 중일 때 추가된 입력은 거부하지 않고 대기열에 등록한다.
- 각 작업은 등록 당시 저장 위치를 유지한다. 작업 시작 시 중복 확인을 다시 수행한다.
- 현재 작업 중지 시 대기열을 유지하고 일시중지한다. 대기열 계속과 대기열 비우기를 제공한다.
- 원본과 하위 폴더는 수정하지 않는다.
- 사용자가 결과 폴더를 직접 지정할 수 있다. 지정한 폴더에 `ex_원래이름.확장자` 사본을 바로 저장한다. 원본 폴더와 동일한 저장 위치는 거부한다.
- 저장 위치를 지정하지 않으면 원본 폴더 안에 실행마다 새로운 결과 폴더를 만든다. 사용자가 기본 위치로 되돌릴 수 있다.
- 기존 보고서는 덮어쓰지 않고 새 보고서에 번호를 붙인다.
- 같은 이름의 결과 파일이 있으면 처리 시작 전에 중복 파일 목록·기존 결과와 원본의 썸네일·전체 경로를 보여준다. 파일마다 덮어쓰기, 다른 이름으로 저장, 건너뛰기를 정한 뒤 선택 적용하며, 취소하면 작업을 시작하지 않는다.
- 덮어쓰기는 검증된 새 사본을 준비한 뒤 기존 결과를 지정된 도구로 휴지통에 보내는 복구 가능한 방식으로만 한다. 원본은 수정하지 않는다. 확인 후 기존 결과가 바뀌거나 휴지통 작업이 실패하면 안전하게 중지한다.
- 다른 이름은 같은 저장 폴더 안에서 원본 확장자를 유지한다. 승인하여 건너뛴 중복은 실패로 집계하지 않는다.
- 형식·픽셀 크기·색상 프로필·DPI를 보존한다. 숨김 정보가 없으면 픽셀을 변경하지 않는다.
- 알려진 숨김 정보가 있으면 그 정보가 차지하는 채널의 최하위 비트만 바꾼다. 해당 값의 변화는 최대 1/255이다. 수학적으로 모든 픽셀이 동일하다는 보장은 하지 않는다.
- 관련 생성 정보를 한 메타데이터 블록에 담은 경우 블록 전체가 제거되어 시드 등도 함께 제거될 수 있다.

## 완료 기준

1. 파일·폴더 버튼 입력과 드래그 입력 모두 동일한 대기열과 파일 처리 흐름으로 이어진다.
2. 일반 생성 메타데이터와 지원하는 숨김 형식에서 프롬프트를 추출할 수 없는 사본을 만든다.
3. 원본 해시와 하위 폴더의 내용이 유지된다.
4. 사본 형식·픽셀 크기, PNG 표시 정보와 JPEG 압축 데이터가 검증된다.
5. 실패한 파일은 성공으로 표시하지 않고, 다른 파일의 처리를 계속한다.
6. 폴더별 성공·실패 결과를 화면과 CSV에 남긴다. 프롬프트 내용은 보고서에 기록하지 않는다.
7. 처리 중 파일·폴더 추가, 등록 순서 보장, 중지 후 대기열 보존·계속, 대기 작업만 비우기를 검증한다.

## 제외 범위와 한계

- 이미지 자체의 복사, 재업로드, 시각적 추론을 이용한 재현 방지
- 알려지지 않은 임의의 스테가노그래피와 미래의 모든 생성 정보 형식에 대한 보장
- 하위 폴더 재귀 처리, 이미지 생성·편집·형식 변환
- PNG·JPG 외 이미지 형식
- 애니메이션 PNG·다중 이미지 JPEG는 실패로 보고한다.
- EXIF 회전이 필요한 파일은 방향 손상을 피하기 위해 실패로 보고한다.
- 파일당 256MB, 5천만 픽셀을 초과하는 이미지는 실패로 보고한다.

인터뷰 종료 후 문서만 저장하고 멈추는 기본 절차 대신, 사용자의 명시적인 실제 구현 요청에 따라 구현까지 진행했다.
