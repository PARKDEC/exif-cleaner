# v1.3.1 검증 기록

검증일: 2026-11-23. 기능 코드: `c2a6396`, 하단 배치 수정: `b935362`.

## 자동 검증

전체 테스트 **51 passed**. 생략·비활성화한 테스트 없음.

- 개별 PNG·JPG 입력은 선택한 파일만 처리하며 같은 폴더의 다른 파일을 처리하지 않음.
- 개별 파일에도 기본·지정 저장 위치, 중복 사전 검사와 원본 보존 적용.
- 실제 첫 번째 이미지 작업을 대기시킨 동안 파일·폴더를 추가하여 FIFO 처리 순서 확인.
- 처리 중 드롭 수락과 파일 선택 버튼을 통한 여러 파일 추가 확인.
- 등록 당시 저장 위치가 작업별로 유지되는지 확인.
- 앞선 대기열 작업에서 생성된 파일이 다음 작업의 중복 모달에 반영되는지 확인.
- 중지 시 현재 파일을 마친 뒤 대기열 보존·일시중지, 계속 시 다음 작업 실행 확인.
- 대기열 비우기는 현재 작업을 중지하거나 파일을 변경하지 않음.
- 중복 모달 취소 시 남은 대기열 일시중지 확인.
- 손상된 이미지가 있어도 이후 작업 처리, 앱 종료 시 대기 작업 미실행 확인.
- 장식용 아이콘 오류가 앱 시작을 막지 않는지 확인.
- 긴 결과 경로와 대기열이 표시되어도 하단 중지·결과 폴더 버튼이 보이는지 확인.

처리 중 입력을 거부하도록 조건을 변경한 변이를 FIFO 테스트가 탐지했다. 검사 후 원래 코드 바이트를 복구하고 작업 트리가 깨끗한지 확인했다.

GUI 테스트는 하나의 Tk 인터프리터와 테스트별 Toplevel 창을 사용하며, 테스트 종료 전에 실제 작업 스레드를 기다린다. 반복적인 인터프리터 초기화 중 발생한 테스트 환경 오류를 피하면서 제품과 같은 단일 Tk 모델에서 검증했다.

## 실제 배포 EXE

- Windows onedir 빌드 성공. 별도 Python 설치 없이 실행되는 런타임 포함.
- 개발용 `TCL_LIBRARY`, `TK_LIBRARY`, `PYTHONHOME`, `PYTHONPATH`를 전달하지 않는 환경에서 배포 EXE 실행.
- 개별 파일 1개와 다른 폴더 1개를 같은 EXE에 전달하여 두 작업의 자동 연속 처리 확인.
- 두 결과 이미지에서 일반 프롬프트 필드가 제거되고 크기가 유지되는지 확인.
- 선택하지 않은 형제 파일은 처리하지 않았고 모든 원본 해시가 유지됨.
- 실제 창에서 파일 추가·폴더 추가·대기열·누적 결과와 하단 버튼 표시 확인.

처리 중 추가는 실제 파일 처리를 사용하는 드롭 콜백·파일 선택 콜백 테스트로 검증했다. 탐색기에서 앱까지 마우스를 이동하는 실제 OS 드래그 자동화는 도구의 창 경계 제약 때문에 수행하지 않았다. 사용자 이미지 대신 합성 테스트 이미지만 사용했다.
