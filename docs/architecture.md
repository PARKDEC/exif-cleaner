# 구조와 검증 계획

## 구성

`main.py`가 DPI 설정과 창을 초기화한다. `ui.py`가 파일·폴더 선택, 네이티브 드롭, 작업 대기열과 진행 표시를 맡는다. 작업 스레드에서 `batch.run_input()`을 호출하고 메시지 큐를 통해 화면에 결과를 전달한다. Tk 위젯과 작업 대기열은 UI 스레드에서만 갱신한다.

`batch.py`는 비재귀 파일 수집, 고유 결과 폴더 생성, 파일별 오류 격리, 중지, 프롬프트를 포함하지 않는 CSV 보고서를 담당한다.

v1.1에서는 `run_folder(..., output_folder=...)`로 저장 폴더를 지정한다. 지정한 디렉터리에 직접 저장하며, `None`이면 기존의 고유 결과 폴더 생성 방식을 사용한다. UI는 입력 폴더를 받기 전에 저장 폴더를 선택할 수 있게 한다. 작업 시작 시 저장 경로를 스레드 인수로 고정하고, 처리 중 저장 위치 변경 버튼을 비활성화한다. 원본과 동일한 경로와 사라진 저장 폴더는 사전에 거부하며, 보고서도 배타적 파일 생성으로 기존 내용을 보호한다.

v1.2에서는 `find_conflicts()`가 읽기 전용으로 기존 결과 파일을 미리 찾고, `dialogs.py`의 모달이 파일 목록과 선택된 기존 결과·원본의 썸네일을 표시한다. 썸네일은 선택된 두 파일만 로딩하여 대량 중복에서도 모든 이미지를 메모리에 보관하지 않는다. 사용자 승인 후 `skip_conflicts`를 고정하여 작업 스레드에 전달한다. 제외된 파일은 별도 상태로 화면·보고서에 기록하며 실패 수에서 제외한다. 취소 시 작업 스레드와 출력 파일을 만들지 않는다. 사전 확인 이후 외부 프로그램이 새 충돌을 만드는 경우에도 마지막 파일 쓰기의 덮어쓰기 방지가 작동하며 오류를 보고한다.

v1.3에서는 `run_input()`이 단일 이미지 또는 비재귀 폴더 입력을 받는다. UI는 입력마다 불변 `QueuedJob`에 원본 경로와 당시 저장 경로를 저장하고 `deque`에 등록한다. 작업 완료·오류 메시지를 받은 UI 스레드가 다음 작업을 꺼내 검증하고 중복 모달을 처리한 뒤, 하나의 작업 스레드를 시작한다. 미리 저장되는 작업 사본은 없고 원본을 수정하지 않는다. 앞 작업이 새로 만든 결과도 다음 작업 시작 시 중복 검사에 반영된다.

중지는 현재 작업을 취소하고 대기열을 일시중지하며, 비우기는 아직 시작하지 않은 작업만 메모리와 화면에서 제거한다. 종료 시 대기 작업을 시작하지 않는다. 여러 파일 선택과 드롭 구역 내부의 모든 하위 위젯에 대한 네이티브 드롭 등록을 지원한다. 결과 표는 작업마다 지우지 않고 세션 내에서 누적한다.

GUI 테스트는 하나의 Tk 런타임과 테스트별 Toplevel 창을 사용하며, 테스트 종료 전에 작업 스레드가 끝났는지 확인한다. 이 구조는 [Python의 Tkinter 스레딩 모델](https://docs.python.org/3/library/tkinter.html#threading-model)에 맞춘다.

v1.4에서는 `ConflictChoice`에 overwrite/rename/skip 선택, 새 이름, 기존 결과 SHA-256을 기록한다. 모달 취소는 `None`으로 구분하며 모든 항목이 결정되어야 적용된다. `run_input()`이 파일마다 선택을 적용하고 실제 저장 경로를 결과·CSV에 기록한다. 이름 변경은 같은 디렉터리·확장자와 파일명 충돌 방지를 검증한다.

덮어쓰기에서는 `clean_image()`가 기존 결과의 확인된 해시를 검사한 뒤 후보 이미지 검증·임시 저장·저장 해시 검증을 먼저 끝낸다. 기존 결과를 다시 검사하고 `recycle.py`에서 사용자가 지정한 `%USERPROFILE%/.codex/Move-ToRecycleBin.ps1`을 실행한다. 전달한 절대 경로와 휴지통 이동 응답을 확인한 후 Windows의 덮어쓰지 않는 rename으로 후보를 게시한다. 기존 결과가 바뀌면 재활용하지 않고, 휴지통 오류는 `RecycleError`로 작업과 대기열을 중지한다. 기존 결과 이동 후 게시 실패 시 기존 파일의 복구 가능 여부와 보존된 후보 위치를 오류에 기록한다.

Windows PowerShell 자식 프로세스는 자체 시스템 모듈 경로를 사용해 부모 PowerShell Core의 모듈 경로와 충돌하지 않게 한다. 실행 정책이나 영구 환경 설정을 바꾸지 않는다. 영구 삭제 API나 대체 삭제 경로는 구현하지 않는다.

`cleaner.py`의 `clean_image(source, destination)`가 단일 진입점이다. 읽기 전용 원본 → 형식 검사 → 후보 사본 생성 → 메모리 검증 → 원본 해시 재확인 → 작업 파일 저장·해시 확인 → Windows에서 덮어쓰지 않는 이름 변경 순서로 처리한다.

`containers.py`는 PNG 청크와 JPEG 세그먼트를 처리한다. 관련 없는 PNG 텍스트와 색상·DPI 청크는 원본 바이트를 보존한다. JPEG의 EXIF/XMP, IPTC, 주석 세그먼트를 제거하고, 압축 데이터·ICC·Adobe/JFIF 세그먼트는 그대로 보존한다.

`stealth.py`는 알려진 alpha/RGB, 압축/비압축 stealth PNGinfo 형식을 감지한다. 식별자만 지우지 않고 선언된 전체 프롬프트 데이터 영역을 덮어쓴다. 알파 채널은 LSB를 1로, RGB 채널은 LSB를 0으로 만든다. 처리 전후 채널 값의 차이를 최대 1로 제한한다. 숨김 정보 처리 시 PNG를 무손실 재압축하되, 유지 대상 표시 청크는 원본 바이트를 다시 사용한다.

## 검증 순서

1. PNG 일반 메타데이터·EXIF, JPEG 무재압축, 네 가지 숨김 형식, 원본 보호 검증
2. 비재귀 폴더 처리, 오류 지속, 결과 폴더 충돌 회피, 중지와 보고서 검증
3. 실제 Tk 창에서 버튼 입력과 Tcl 경로를 사용하는 드롭 콜백 검증
4. 현재 화면 배율의 실제 창을 시각적으로 확인
5. Python이 함께 포함된 Windows 실행 폴더를 빌드하고 실행 확인

검증이 실패한 이미지 후보는 최종 `ex_` 이름으로 공개하지 않는다. 디스크 쓰기 실패 시 `_processing` 아래 미완성 작업 파일이 남을 수 있다. 자동 영구 삭제는 수행하지 않는다.
