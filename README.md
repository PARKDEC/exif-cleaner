# Exif Cleaner

Exif Cleaner는 이미지를 공유하기 전에 이미지 생성 정보를 제거한 사본을 만들어 주는 로컬 애플리케이션입니다. 
이미지 업로드, 계정, API 키가 필요하지 않습니다.

## 다운로드

[GitHub 릴리스 페이지](https://github.com/PARKDEC/exif-cleaner/releases/latest)에서 ZIP 파일을 내려받아 전체 압축을 해제한 후 `ExifCleaner.exe`를 실행하십시오.

제거 대상은 EXIF에 한정되지 않습니다. PNG 텍스트, XMP, IPTC 및 지원되는 숨김 생성 정보도 함께 제거합니다.

## 사용 방법

1. 배포 폴더의 `ExifCleaner.exe`를 실행합니다.
2. 사본을 원하는 위치에 저장하려면 먼저 저장 폴더를 선택합니다. 사본은 선택한 폴더에 저장됩니다.
3. **파일 추가**로 PNG·JPG 이미지를 선택하거나 **폴더 추가**로 폴더를 선택합니다. 여러 개의 파일 또는 폴더를 드롭 구역에 끌어다 놓을 수도 있습니다.
4. 처리 중에도 파일과 폴더를 추가할 수 있습니다. 추가한 순서대로 대기열에 등록되며, 현재 작업이 끝나면 다음 작업이 자동으로 처리됩니다.
5. 처리가 끝나면 **결과 폴더 열기**를 통해 결과를 확인할 수 있습니다.

### 저장 위치와 파일 이름

직접 지정한 저장 폴더에는 `ex_원래이름.확장자` 형식의 사본이 저장됩니다. 저장 폴더 지정은 앱을 닫을 때까지 유지되며, 처리 중에는 변경할 수 없습니다. 원본 폴더와 같은 위치는 선택할 수 없습니다.

각 작업은 대기열에 추가된 시점의 저장 위치를 사용합니다. 따라서 대기열을 일시중지한 상태에서 저장 위치를 변경하더라도, 이미 등록된 작업의 위치는 바뀌지 않습니다.

### 동일한 이름의 파일이 있는 경우

동일한 이름의 결과 파일이 있으면 해당 작업이 시작되기 전에 확인 창이 표시됩니다. 앞선 대기열 작업에서 방금 생성된 파일도 이 단계에서 함께 확인합니다. 겹치는 파일 목록에서 항목을 선택하면 기존 결과 이미지와 이번 원본의 썸네일, 기존 파일의 전체 경로, 저장 예정 경로를 확인할 수 있습니다.

파일별로 다음 중 하나를 선택한 후 **선택 적용**을 누릅니다. 모든 중복 파일에 대해 선택을 완료해야 적용할 수 있습니다.

- **덮어쓰기:** 새 사본의 이미지 및 저장 검증을 마친 후, 기존 결과를 휴지통으로 이동하고 새 사본을 같은 이름으로 저장합니다. 기존 결과는 휴지통에서 복구할 수 있으며, 원본 이미지는 수정하지 않습니다.
- **다른 이름으로 저장:** 같은 결과 폴더에서 사용할 새 이름을 입력합니다. 겹치지 않는 이름이 자동으로 제안되며, 확장자를 생략하면 원본 확장자가 붙습니다. 다른 경로나 형식으로 변경하는 이름은 허용되지 않습니다.
- **건너뛰기:** 해당 파일은 처리하지 않으며, 중복 제외로 집계합니다.
- **취소:** 현재 작업 전체를 시작하지 않고 남은 대기열을 일시중지합니다. 확인 창에서 지정한 선택 사항도 적용되지 않습니다.

확인 이후 기존 결과가 변경된 경우에는 덮어쓰지 않습니다. 휴지통 이동에 실패하면 해당 작업을 중지하고 대기열도 일시중지하며, 영구 삭제로 전환하지 않습니다.

휴지통 덮어쓰기는 이 PC의 `%USERPROFILE%\.codex\Move-ToRecycleBin.ps1` 및 Windows PowerShell을 사용하며, 로컬 고정 드라이브에서만 지원됩니다. 해당 도구가 없거나 다른 환경인 경우에는 "다른 이름으로 저장" 또는 "건너뛰기"를 사용하시기 바랍니다.

손상되었거나 지원하지 않는 파일은 썸네일 대신 "미리보기 불가" 안내가 표시됩니다. 처리 보고서에는 실제 저장 경로와 기존 결과의 휴지통 이동 내역이 함께 기록됩니다. 기존 보고서는 보존되며, 새 보고서에는 번호가 부여됩니다.

### 저장 폴더를 지정하지 않은 경우

저장 폴더를 선택하지 않았거나 **기본 위치**를 누른 경우, 폴더 작업은 해당 폴더 안에, 개별 파일 작업은 해당 파일이 있는 폴더 안에 `prompt_cleaned_날짜_시간` 결과 폴더를 매번 새로 생성합니다.

개별 파일을 추가하더라도 같은 폴더의 다른 파일은 처리하지 않으며, 폴더를 추가한 경우에도 하위 폴더는 처리하지 않습니다. 지원하는 확장자는 `.png`, `.jpg`, `.jpeg`입니다. 파일명에 한글, 공백, 중괄호가 포함되어 있어도 처리할 수 있습니다.

### 결과 확인

결과 표의 행을 더블클릭하면 처리 내용을 확인할 수 있습니다. 표에는 여러 작업의 내역이 누적되며, `처리결과.csv`에도 작업별 결과가 기록됩니다. 프롬프트 내용은 기록하지 않습니다.

### 작업 중지 및 대기열 관리

**현재 작업 중지**는 현재 처리 중인 파일을 안전하게 마친 후 해당 작업의 나머지를 중지합니다. 대기 중인 다른 작업은 그대로 유지됩니다. **대기열 계속**을 누르면 남은 작업부터 이어서 처리합니다. 중지된 폴더 작업의 미처리 파일까지 다시 처리하려면 해당 폴더를 다시 추가하시기 바랍니다.

**대기열 비우기**는 아직 시작하지 않은 작업만 취소하며, 현재 처리 중인 작업과 디스크의 파일에는 영향을 주지 않습니다. 대기열은 앱이 실행되는 동안에만 유지됩니다. 앱을 닫으면 현재 파일을 안전하게 마친 후 종료하며, 대기 중인 작업은 실행되지 않습니다.

배포 폴더의 `_internal`은 실행에 필요한 파일입니다. `ExifCleaner.exe`와 같은 폴더에 함께 보관하십시오. Python을 별도로 설치할 필요는 없습니다.

## 처리 범위

- PNG의 `Description`, `Comment`, `parameters`, `prompt`, `workflow` 등 알려진 생성 정보 필드 및 EXIF/XMP
- JPEG의 EXIF/XMP, IPTC, 주석 세그먼트
- `stealth_pngcomp`, `stealth_pnginfo`, `stealth_rgbcomp`, `stealth_rgbinfo` 방식의 숨김 정보
- 알려진 데이터 외의 PNG 작성자 등 텍스트, ICC 색상 프로필, 감마 및 DPI 등 표시 정보는 보존합니다.

JPEG는 재압축하지 않습니다. 숨김 정보가 없는 PNG 역시 이미지 데이터를 그대로 유지합니다. 숨김 정보가 있는 PNG는 데이터가 담긴 채널의 최하위 비트를 변경한 후 무손실로 재압축합니다. 형식과 크기는 유지되며, 변경된 채널 값의 차이는 최대 1/255입니다. 파일 용량은 달라질 수 있습니다.

## 유의 사항

본 앱은 알려진 저장 방식에 의한 생성 정보 노출을 줄이는 도구입니다. 파일명 자체에 프롬프트를 기재하였다면 파일명을 직접 변경하시기 바랍니다. 이미지 복사 후 재업로드, 시각적 추론, 알려지지 않은 숨김 방식까지 차단하지는 않습니다. 실제 사용 중인 이미지 한 장으로 NAI Inspect에서 결과를 확인하실 것을 권장합니다.

애니메이션 PNG, 다중 이미지 JPEG, EXIF 회전이 필요한 사진, 256MB 또는 5천만 픽셀을 초과하는 파일, 손상된 파일은 처리되지 않으며 실패 사유가 표시됩니다. `_processing`은 작업용 폴더이므로, 쓰기 실패 시 남은 파일을 공유하지 마시기 바랍니다.

## 개발

Python 3.14에서 개발 및 검증하였습니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe build.py --destination dist --work-root work
```

빌드 스크립트는 기존 `ExifCleaner` 배포 폴더를 덮어쓰지 않으므로, 새 목적지를 지정하시기 바랍니다. 테스트 자료도 자동으로 삭제하지 않으며 `work/test-artifacts`에 보관됩니다.

설계 및 요구 사항은 `docs/intent.md`와 `docs/architecture.md`에 기술되어 있습니다.
